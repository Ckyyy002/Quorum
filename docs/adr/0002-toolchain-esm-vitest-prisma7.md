# ADR-0002: ESM + Vitest for the API, Prisma 7 with the pg driver adapter

- Status: Partly superseded. The ESM + Vitest part is superseded by [ADR-0003](0003-jest-for-fp-compliance.md); the Prisma 7, TypeScript ~6.0 and ESLint parts still apply.
- Date: 2026-11-24

## Context
The plan named Jest for tests. NestJS 12, the current release, now generates an ES-module project
(`"type": "module"`, `nodenext`) that uses Vitest. Jest's ESM support is still experimental, and keeping
Jest would mean converting the app back to CommonJS. Prisma 7 also changed its setup: the client is
generated into the source tree, and it connects through a JS driver adapter instead of a Rust engine.

## Decision
- The API stays ESM and uses **Vitest** with **Supertest**. One `vitest.config.ts` defines two projects,
  `unit` (`src/**/*.spec.ts`) and `e2e` (`test/**/*.e2e-spec.ts`, run serially), so `test:cov` measures
  both together against a 70% threshold.
- **Prisma 7.10** (stable; 8.0 is still RC): generator `prisma-client` → `src/generated/prisma` (gitignored,
  regenerated by the api `postinstall`), `prisma.config.ts` for the datasource URL, `@prisma/adapter-pg` at runtime.
- TypeScript is pinned to **~6.0**. TS 7 (native) is not yet supported by typescript-eslint.
- Linting uses **ESLint** (one flat config at the root) rather than the oxlint that the generators set up,
  so there is one lint tool for both apps, with type-aware rules.

## Alternatives considered
- Jest + CommonJS. Matches the original plan, but it works against the framework default and adds ts-jest config.
- Prisma 8 RC. Not stable yet; this is a graded project with a fixed deadline.

## Consequences
- Test code reads the same as Jest (`describe/it/expect`); use `vi.fn()` instead of `jest.fn()`.
- Relative imports in the API need the `.js` extension (ESM rule).
- Unit tests of decorated classes depend on `reflect-metadata`, which is loaded via `setupFiles`.
